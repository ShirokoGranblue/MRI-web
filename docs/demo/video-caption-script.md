# MRI 系统 A 方式无口播字幕操作脚本

## 录制规格

- 画面：1920×1080，浏览器缩放 100%。
- 时长：约 17 分钟。
- 声音：不录制口播，不添加合成语音。
- 字幕：顶部章节标题、底部业务解释、关键位置证据标注。
- 浏览器：医生和患者使用两个隔离会话，避免 localStorage 相互覆盖。
- 验证账号：医生 `admin/admin123`；患者在视频中注册 `patient01`。
- 测试数据：仅用于录制和端到端验证，完成后执行全量运行数据清理。

## 录制前准备

1. 执行 `scripts/db/clear-runtime-data.ps1`，确认业务表、患者账号、Redis 和 MinIO 均为空。
2. 执行 `scripts/demo/01-start-infra.ps1`。
3. 执行 `scripts/demo/02-start-services.ps1`。
4. 在 `mri-frontend` 执行 `npm run dev`。
5. 准备一张不包含隐私信息的 PNG 或 JPG 影像验证文件。
6. 打开两个独立浏览器上下文：
   - 窗口 A：患者。
   - 窗口 B：医生。
7. 提前确认 5173、8080、9001、9101、8848 均可访问。

## 00:00–00:50 系统定位

画面：

1. 打开系统登录页。
2. 缓慢展示系统名称、医生登录和患者注册入口。

顶部字幕：

> 医院核磁共振图像信息管理系统

底部字幕：

> 系统把患者资料、检查申请、检查排程、影像归档和诊断报告连接为完整业务链，并通过医生与患者角色实现数据权限隔离。

证据标注：

> Java 21｜Spring Boot 3｜Spring Cloud｜React

## 00:50–02:00 技术架构

画面：

1. 打开项目架构图或 README 技术栈。
2. 按顺序高亮前端、Gateway、五个业务服务和基础设施。

顶部字幕：

> 技术架构与服务边界

底部字幕依次出现：

> React + Vite 提供医生和患者双角色界面。

> Spring Cloud Gateway 统一处理 API 路由、JWT 校验、401/403 区分和角色权限。

> 认证、患者、检查、影像、报告五个服务通过 Nacos 注册发现，并使用 OpenFeign 完成已有远程调用。

> MySQL 保存业务数据，Redis 提供缓存和 token 黑名单，MinIO 保存真实影像对象。

## 02:00–03:30 启动与注册中心

画面：

1. 终端执行 `scripts/demo/01-start-infra.ps1`。
2. 显示 MySQL、Redis、Nacos、MinIO 为运行状态。
3. 终端执行 `scripts/demo/02-start-services.ps1`。
4. 打开 Nacos 服务列表，展示六个服务。
5. 打开认证服务 Swagger `http://localhost:9001/swagger-ui.html`。
6. 打开 MinIO 控制台 `http://localhost:9101`。

顶部字幕：

> 基础设施、服务注册与端口隔离

底部字幕：

> 认证服务及 Swagger 使用 9001；MinIO API 使用 9000，管理控制台使用 9101，避免端口冲突。

> Nacos 负责服务注册、发现和配置管理，Gateway 根据服务名转发请求。

## 03:30–05:00 患者注册与登录认证

使用患者窗口 A。

操作：

1. 点击“患者注册”。
2. 姓名输入 `张三`。
3. 停顿 2 秒，展示用户名自动带出 `张三`。
4. 将用户名改为 `patient01`。
5. 密码和确认密码输入 `patient123`。
6. 点击“注册患者账号”。
7. 停顿展示顶部绿色“注册成功”提示。
8. 使用 `patient01/patient123` 登录。

顶部字幕：

> 患者注册｜用户名唯一｜密码哈希保存

底部字幕：

> 患者姓名允许重复，登录用户名必须唯一。注册接口不接收角色字段，服务端固定授予 PATIENT，避免越权注册医生账号。

证据标注：

> POST /api/auth/register → PATIENT

## 05:00–06:30 患者首次建档与禁忌症

操作：

1. 登录后自动进入“我的资料”。
2. 输入性别、出生日期和联系电话。
3. “是否存在 MRI 禁忌症”选择“有禁忌症”。
4. 类型选择“金属植入物”。
5. 说明输入“左膝钛合金内固定”。
6. 严重程度选择“高”。
7. 点击“提交建档”。
8. 展示顶部成功提示和服务端生成的患者编号。

顶部字幕：

> 患者本人建档｜资料与禁忌症原子保存

底部字幕：

> 基本资料和完整禁忌症列表在患者服务的同一个事务中保存。医生不能代替患者新增、修改或删除患者档案。

## 06:30–07:30 医生只读患者资料

切换医生窗口 B。

操作：

1. 使用 `admin/admin123` 登录。
2. 打开“患者档案”。
3. 搜索“张三”或 `patient01` 对应患者编号。
4. 打开详情。
5. 展示基本资料、禁忌症和检查历史。
6. 将鼠标停留在操作列，证明只有“详情”，没有新增、编辑、删除按钮。

顶部字幕：

> admin 作为医生｜患者资料只读

底部字幕：

> 医生负责后续医疗业务处理，但患者基础资料只能由患者本人维护。前端隐藏写入口，Gateway 同时拒绝医生对患者写接口的访问。

## 07:30–10:30 医生业务流程

### 07:30–08:20 检查申请

1. 打开“检查申请”。
2. 选择患者张三。
3. 检查项目输入“头颅 MRI 平扫”。
4. 临床诊断输入“持续性头痛”。
5. 优先级选择“普通”。
6. 点击新增。

字幕：

> 检查申请描述“为什么检查、检查什么”，并关联患者。

### 08:20–09:00 检查排程

1. 选中刚创建的检查申请。
2. 检查室输入 `MRI-01`。
3. 设置预约时间。
4. 技师输入“李技师”。
5. 保存排程。

字幕：

> 检查排程把申请落实到具体设备、时间和执行人员，用于安排检查资源并避免业务记录失去执行依据。

### 09:00–09:30 检查执行

1. 点击“开始检查”。
2. 展示顶部成功提示和“检查中”状态。
3. 点击“完成检查”。
4. 展示“已完成”状态。

字幕：

> 状态机阻止越级操作：待检查 → 检查中 → 已完成。

### 09:30–10:30 影像归档与上传

1. 打开“影像归档”。
2. 选择已完成检查并创建 Study。
3. 添加序列“AX T2”。
4. 选择准备好的影像文件。
5. 点击上传。
6. 展示顶部上传成功提示和真实缩略图。
7. 快速切到 MinIO 控制台，展示 `mri-images` 中新增对象。

字幕：

> 文件内容保存到 MinIO；MySQL 保存 Study、Series、文件名、对象路径和校验值。

## 10:30–11:30 患者发布前进度

切换患者窗口 A，不手动刷新。

操作：

1. 等待不超过 5 秒。
2. 打开“我的检查”，展示检查和排程状态。
3. 打开“我的影像”，展示 Study 与文件数量。
4. 点击影像区域，展示“报告发布后开放”。
5. 打开“我的报告”，此时为空或只显示处理状态。

顶部字幕：

> 5 秒静默刷新｜患者只读进度

底部字幕：

> 患者门户沿用 REST 接口每 5 秒刷新；页面进入后台时暂停。报告发布前患者只能看进度，不能读取影像文件或报告正文。

## 11:30–13:00 报告处理与发布

切换医生窗口 B。

操作：

1. 打开“诊断报告”。
2. 选择刚完成的检查和影像。
3. 影像所见输入“颅内未见明显占位性病变”。
4. 诊断意见输入“头颅 MRI 平扫未见明显异常”。
5. 新增报告。
6. 点击“提交”。
7. 点击“审核”。
8. 点击“发布”。
9. 每一步停顿展示顶部提示和状态变化。

顶部字幕：

> 草稿 → 待审核 → 已审核 → 已发布

底部字幕：

> 报告发布是患者查看诊断正文和影像内容的安全边界。发布同时把检查状态回写为“已出报告”。

## 13:00–14:00 患者查看报告和影像

切换患者窗口 A。

操作：

1. 等待不超过 5 秒。
2. 打开“我的报告”，展示完整影像所见和诊断意见。
3. 打开“我的影像”。
4. 点击“查看影像”。
5. 展示只读影像预览。

顶部字幕：

> 报告发布后开放本人内容

底部字幕：

> 报告服务仅在 PUBLISHED 状态返回正文；影像服务同时校验患者归属和报告发布状态，避免跨患者或提前查看。

## 14:00–14:40 401、403 与顶部提示

操作：

1. 在开发者工具或 API 客户端使用患者 token 调用医生写接口。
2. 展示 HTTP 403 和“当前账号没有执行此操作的权限”。
3. 回到患者页面，证明账号仍保持登录。
4. 展示患者导航中没有“操作记录”。

顶部字幕：

> 401 登录失效｜403 权限不足

底部字幕：

> 401 会清理本地会话并要求重新登录；403 只提示无权限，不错误退出。页面不显示 HTTP 代码、Java 异常或网络技术文本。
