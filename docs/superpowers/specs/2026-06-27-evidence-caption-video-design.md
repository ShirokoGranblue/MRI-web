# MRI 证据链式字幕演示视频设计

## 1. 目标

制作一段约 17 分钟、无口播、以操作画面和字幕说明为主的系统验证视频。视频必须让验收人员无需猜测即可确认 10 项技术指标均有真实实现和运行证据，同时讲清楚：

- 项目解决的医疗业务问题；
- 患者、检查申请、排程、影像和报告之间的业务关系；
- 项目的技术栈和微服务架构；
- 各技术在项目中的实际用途；
- 每项技术指标对应的代码、操作和运行结果；
- 典型开发难点及其解决和验证过程。

## 2. 观众和表达原则

主要观众是项目验收人员。默认观众了解 Java Web 基础，但不会提前阅读项目源码。

表达遵循以下原则：

1. 先给结论，再展示操作证据；
2. 一项技术指标至少包含一段真实运行画面；
3. 每个画面说明“正在做什么、用了什么技术、结果证明了什么”；
4. 业务页面使用用户语言，技术字幕使用准确的技术名词；
5. 不用快速闪过的终端日志代替明确证据；
6. 不把尚未实现的能力描述为已实现；
7. Git 推送必须展示远程仓库结果；
8. 测试、接口数量等数字以录制当日实际输出为准。

## 3. 视频形式

采用“方案 A：证据链式字幕演示”，少量插入架构卡片。

画面由三类内容组成：

- **说明卡片**：项目定位、架构图、开发难点、完成情况表；
- **真实系统操作**：浏览器业务页面、Nacos、MinIO、Swagger；
- **真实终端证据**：脚本执行、测试结果、Redis key、Git 命令。

全程不录口播，使用三层字幕：

1. 顶部章节条：显示当前章节和对应考核项；
2. 底部说明字幕：解释当前操作及技术含义；
3. 结果标签：在关键输出旁显示绿色成功标记或橙色对照说明。

示例：

```text
顶部：技术指标 8｜API 服务网关
底部：前端只访问 8080 网关，由 Gateway 完成 JWT 校验和服务路由
结果：✓ 无 Token 被拒绝　✓ 携带 Token 后访问成功
```

## 4. 画面和字幕规范

### 4.1 画面

- 分辨率：1920×1080；
- 比例：16:9；
- 浏览器缩放：110%～125%；
- PowerShell 字号：20～24；
- 编辑器只展示与当前考核点直接相关的代码；
- 录制前关闭微信、邮件、通知和无关窗口；
- 浏览器预先打开必要标签页，减少现场输入 URL；
- 终端使用统一工作目录 `C:\Users\l2653\Desktop\java-web`。

### 4.2 字幕

- 主字幕为白色，使用深色半透明背景；
- 技术名词使用蓝色；
- 成功结论使用绿色；
- 失败对照或拒绝结果使用橙色；
- 单屏字幕不超过三行；
- 每行尽量不超过 24 个汉字；
- 普通字幕至少停留 2.5 秒；
- 关键结论至少停留 3 秒；
- 命令执行期间使用简短字幕，不遮挡关键输出；
- 不显示大段与当前操作无关的说明。

### 4.3 隐私和安全

- 默认账号显示为医生验证账号；
- 密码在录制前预填，不录制逐字符输入；
- 不展示本机私人目录、聊天窗口或敏感 token 全文；
- JWT 只显示前后少量字符，或直接标注“已取得访问凭证”；
- Git 远程仓库必须是允许公开展示的仓库。

## 6. 业务主线设计

业务演示只创建一套可追踪的测试数据，统一使用明显的演示名称：

- 患者编号：`VIDEO-001`；
- 患者姓名：`视频演示患者`；
- MRI 禁忌症：`无金属植入物`；
- 检查项目：`头颅 MRI 平扫`；
- 临床诊断：`反复头痛待查`；
- 优先级：`加急`；
- 检查室：`MRI-01`；
- 技师：`演示技师`；
- 排程时间：录制次日 09:30；
- 影像描述：`头颅 MRI 平扫影像`；
- 序列名称：`T1_AX`；
- 体位：`头部`；
- 报告影像所见：`颅内未见明显异常信号。`；
- 诊断意见：`头颅 MRI 平扫未见明显异常。`。

业务顺序固定为：

```text
新增患者
  -> 登记 MRI 禁忌症
  -> 创建检查申请
  -> 创建检查排程
  -> 开始检查
  -> 完成检查
  -> 保存影像检查
  -> 添加序列
  -> 上传影像文件
  -> 查看真实缩略图
  -> 创建报告
  -> 提交审核
  -> 审核通过
  -> 发布报告
  -> 检查状态变为已出报告
```

检查申请和排程必须使用字幕明确区分：

```text
检查申请：说明患者为什么做、做什么检查
检查排程：说明什么时候、在哪个检查室、由哪位技师执行
```

不得声称当前系统已经实现设备冲突检测、技师冲突检测、短信提醒或完整日历排班。

## 7. 原始 10 项考核证据设计

### 7.1 接口文档和不少于 50 个接口

操作证据：

1. 打开任一服务 Swagger；
2. 展示接口分组；
3. 执行 `scripts/demo/04-api-docs-count.ps1`；
4. 停留显示五个服务分项数量和 `Total APIs: 82`。

字幕结论：

```text
✓ 五个服务均自动生成 OpenAPI 文档
✓ 当前共 82 个接口，高于 50 个要求
```

### 7.2 Redis 中间件和数据库缓存

操作证据：

1. 执行 `scripts/demo/05-redis-cache.ps1`；
2. 展示首次请求填充缓存；
3. 展示第二次查询；
4. 展示 `mri:*` Redis key；
5. 可补充展示患者或影像修改后缓存被清理。

字幕结论：

```text
Redis 用于患者详情、影像详情和预览清单缓存
数据修改后主动删除缓存，避免返回旧数据
```

### 7.3 单元测试及执行结果

操作证据：

1. 快速展示两个有代表性的测试文件；
2. 执行 `mvn clean test`；
3. 展示 `BUILD SUCCESS`；
4. 显示后端 94 个测试、失败 0；
5. 执行 `npm test`；
6. 显示前端 13 个测试通过；
7. 执行 `npm run build`，显示生产构建成功。

字幕结论：

```text
✓ 后端 94 个测试通过
✓ 前端 13 个回归测试通过
✓ 前端生产构建成功
```

### 7.4 Git 提交和远程推送

操作证据：

1. `git status --short`；
2. `git diff --stat`；
3. `git add`；
4. `git commit`；
5. `git log --oneline -5`；
6. `git push`；
7. 打开远程仓库，显示最新提交。

字幕结论：

```text
代码已完成本地版本提交并推送远程仓库
远程页面可核对提交时间、提交说明和文件变化
```

不得只运行 `10-git-demo.ps1` 后立即切走，必须展示远程仓库结果。

### 7.5 登录认证

操作证据：

1. 无 token 调用患者接口；
2. 显示 401 拒绝；
3. 登录 `admin/admin123`；
4. 登录后访问患者接口成功；
5. 前端进入工作台；
6. 可选：退出后旧 token 再次失败。

字幕结论：

```text
认证服务签发 JWT
网关统一验证签名、有效期、角色和 Redis 黑名单
```

### 7.6 服务注册与发现

操作证据：

1. 打开 Nacos 服务列表；
2. 展示五个业务服务和网关；
3. 执行服务停止脚本；
4. 刷新观察影像服务实例下线；
5. 重启服务；
6. 刷新观察实例恢复。

字幕结论：

```text
服务启动自动注册，停止后自动注销
网关和 OpenFeign 通过服务名发现可用实例
```

### 7.7 多服务数据交换和远程调用

操作证据：

1. 执行 `scripts/demo/07-feign-remote-call.ps1`；
2. 展示检查服务创建申请；
3. 标注检查服务远程校验患者；
4. 展示影像归档前校验检查状态；
5. 展示报告发布后回写检查状态；
6. 短暂展示对应 Feign 接口代码。

字幕结论：

```text
检查服务 -> 患者服务：校验患者
患者服务 -> 检查服务：查询检查历史
影像服务 -> 检查服务：校验检查状态
报告服务 -> 检查/影像服务：校验并回写状态
```

### 7.8 API 服务网关

操作证据：

1. 执行 `scripts/demo/08-gateway-access.ps1`；
2. 无 token 请求被拒绝；
3. 有 token 请求成功；
4. 展示前端请求地址统一为 `/api/**`；
5. 可短暂展示 Gateway 路由配置。

字幕结论：

```text
外部请求只访问 8080 网关
网关负责鉴权，并按路径路由到不同微服务
```

### 7.9 配置中心动态刷新

操作证据：

1. 在系统设置页显示当前水印和下载开关；
2. 执行 `scripts/demo/09-nacos-config-refresh.ps1`；
3. 等待 5 秒；
4. 点击重新读取设置；
5. 展示水印和下载开关发生变化；
6. 不重启影像服务。

字幕结论：

```text
配置保存在 Nacos Config
运行中无需重启即可刷新业务配置
```

### 7.10 开发难点和解决过程

使用四张简短证据卡：

1. 版本兼容：Spring Boot、Spring Cloud、Spring Cloud Alibaba 使用统一 BOM；
2. JWT 和登出：网关鉴权 + Redis token 黑名单；
3. 缓存一致性：查询填充、修改和删除主动失效；
4. MinIO 上传 500：启动脚本漏 MinIO、9001 端口冲突、桶不存在、multipart 绑定，最终逐层修复并端到端验证。

每张卡使用固定格式：

```text
现象
原因
解决
验证
```

## 8. 录制前准备

1. 确认所有修复已提交；
2. 确认远程仓库可推送；
3. 删除或重命名已有 `VIDEO-001` 测试数据；
4. 准备一张可公开展示的 MRI 示例图片；
5. 启动屏幕录制软件，设置为 1080p；
6. 关闭通知；
7. 打开 PowerShell，并进入项目根目录；
8. 打开浏览器标签：
   - `http://localhost:5173`
   - `http://localhost:8848/nacos`
   - `http://localhost:9101`
   - `http://localhost:9001/swagger-ui.html`

   - 根 `pom.xml`

   - 代表性测试文件
10. 准备字幕卡和架构图。

## 9. 失败处理设计

录制过程中不现场长时间排错。遇到问题按以下规则处理：

- 服务未启动：暂停录制，修复后从当前章节重新录；
- 登录 401：清除浏览器本地会话并重新登录；
- MinIO 上传失败：检查 `docker compose ps minio`、9000 健康状态和桶；
- Nacos 页面未更新：等待 5 秒后刷新；
- 动态配置未刷新：核对 dataId `mri-image-service.yaml`；
- Git 没有新改动：在录制前预留本次视频脚本或说明文档作为合法提交内容；
- 业务数据重复：清理 `VIDEO-001` 后重新录业务章节；
- 测试失败：停止录制，修复并重新运行完整测试，不在成片中保留失败状态。

## 10. 验收标准

最终成片必须满足：

- 10 项技术指标全部出现明确章节编号；
- 每项要求至少有一条运行证据；
- 82 个接口统计是现场脚本输出；
- 后端 94 个和前端 13 个测试是现场执行结果；
- Git 推送后展示远程仓库；
- 业务主线完整走到报告发布；
- 排程作用说明准确；
- 架构图中包含前端、网关、五个业务服务、Nacos、Redis、MySQL、MinIO；
- MinIO 控制台使用 9101，认证服务使用 9001；
- 不出现无法解释的 HTTP 500、原始技术错误或遗留测试文件；
- 结束页明确显示 10 项全部完成。
